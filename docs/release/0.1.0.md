# gisknife 0.1.0：发布验收单

**结论：本地文件处理通过候选版验收，源码已公开，尚未向 npm 或 PyPI 发包。** 0.1.0 首发验收范围为已有文件的坐标与格式转换、检查、空间分析和预览生成。联网取数保留为 Beta，不承诺覆盖或可用性。公共包索引安装仍待验证，网站改动未部署。

本地验收记录截至 2026-11-20 UTC，覆盖 `gisknife` 基线 `354978d` 和 `Cimtooldevelopment` 基线 `5ab052b` 之后的改动。网站改动不在本仓库提交范围内。此次本地验收的包目录是 `tmp/rc-local-first/`，其中七个 npm tarball、一个 wheel、一个 sdist；用 [SHA256SUMS](SHA256SUMS) 识别，不要混用先前的 `tmp/rc-final/`、`tmp/candidate/` 或 `tmp/release/`。GitHub Actions 从提交重新构建，使用各自的产物校验清单。

## 修复了什么

| 原问题 | 改后的可观察行为 |
|---|---|
| 原文件可能被原地覆盖 | CLI、MCP、引擎检查输入输出是否为同一文件，包括符号链接和硬链接；MCP 的 `.json` 默认写入不同文件 |
| 同名区、父市或父边界被当作请求结果 | 已知歧义给候选；不能核实的区县不猜；请求子区不退回父区；街道按行政编码或父区多数面积筛选 |
| 英尺被当作米，SQL 输出被错标为 WGS84 | 米制测量按轴单位换算；单位不明则报错；SQL 保留类型携带的 CRS，未标记的空间输出要求 `--result-crs` |
| 空 CSV 坐标变成零 | 空白和非法行计入 `skippedCount`；合法的 `0` 保留，追加的 WGS84 列可直接用于后续点转换 |
| GPX 丢点、报出的数量不等于文件内容 | MultiPoint 展开为航点；拒绝多边形等不能表达的几何；轻格式统计写出内容；回读验证轻重格式混转 |
| Python 切目录导致相对路径失效 | `uv --project` 指向引擎，输入、输出和 SQL 文件仍相对于调用者的工作目录 |
| Overture 未安装或取数失败也报告成功 | 需要引擎时真正执行；无 `uv` 返回非零，不生成假文件。提取记录发布版本，超限报错，成功后才替换目标 |
| 预览将属性当 HTML 解释 | 弹窗用文本节点；本地选择器限制来源、提交大小和坐标范围。预览 HTML 仍包含数据，不能当成脱敏产物 |

另修正了 A2UI 消息结构和 WebMCP 参数与网页不一致的问题。Skill 只安装说明，不安装 CLI；GeoTIFF 只支持元数据检查，不把可选依赖写成已有功能。

## 本地首发验收

运行 `bash scripts/smoke-package.sh tmp/rc-local-first`。脚本在新目录校验并安装候选包，用合成样本检查 CSV 坐标转换、GeoPackage 往返、几何检查、SQL 面积和 HTML 内容；没有 `uv` 时轻量操作仍可用，重格式转换明确报错且不写文件。验收不请求任何在线地图数据，但首次准备依赖和 DuckDB 扩展可能联网。生成的 HTML 包含数据，打开后仍会加载远程地图资源。

## 联网 Beta 实测记录

以下是先前运行的真实取数结果。文件在忽略目录 `tmp/acceptance/`，不随发布包分发；[文件大小与哈希](job-evidence.json)可用于核对留样。`bash scripts/acceptance-jobs.sh` 用于单独诊断数据源，依赖 Node、`uv`、`jq`、已构建的 CLI 和外网。数据源失败时诊断仍返回失败，但不影响本地首发验收。

| 任务 | 检查与结果 |
|---|---|
| 华盛顿消歧 → 边界 → GeoPackage | 裸 `Washington` 给两个候选；明确 D.C. 后本次命中 US Census TIGER，GPKG 回读 1 个面，范围约 `[-77.120,38.792,-76.909,38.996]`。较早一次使用了明确标记的 Nominatim 回退 |
| 佛山区划与南山街道 | 佛山 DataV 返回五区；南山 OSM 返回南头、南山、沙河、蛇口、招商、粤海、桃源、西丽八街道。不是对全国街道覆盖或数据出版许可的证明 |
| Palo Alto 道路 | 同一请求框 `[-122.17,37.41,-122.165,37.415]` 得到 Overpass 49 条、Overture `2026-11-18.0` 46 条；GeoParquet 回读通过。返回相交要素、不是几何裁剪，所以道路可伸出请求框；两源不应比较条数判断对错 |
| 测绘 CSV | `4547: 500000,2500000` 与 `4526: 38500000,2500000` 均得到 `114,22.5978229`；中文业务列保留。各有 1 行有效、1 行空坐标跳过 |
| QA → SQL 面积 → HTML | 八个街道全数回读，QA 为 0 个问题，SQL 得到八个正面积，HTML 预览已落盘。南头约 `9,993,447 m²`。普通 SQL 不会自动纠正投影或单位 |

**重复运行的反例：** 单项成功后，再次用 `--no-cache` 从零串跑时，南山两种查询均遇到 Overpass 镜像 502、504 或超时，脚本停止，没有退回父区或把旧文件当成成功。首发不分发样本、不配置默认备用索引。以后若要承诺街道覆盖，须用许可明确的版本化数据源，在 Overpass 不可用且无缓存时核验覆盖、来源和坐标系。

## 上线顺序与回滚

1. **本地冻结。** 从空包目录运行 `pnpm install --frozen-lockfile`、`bash scripts/pack-candidate.sh <空目录>`、`pnpm typecheck && pnpm test`、`uv run --project python/gisknife-engine --locked --extra dev pytest python/gisknife-engine/tests`、`bash scripts/smoke-package.sh <包目录>`。复核打包清单与许可证。改代码或包内容后重新冻结，不沿用旧哈希。
2. **GitHub 验收。** [`reed-soul/gisknife`](https://github.com/reed-soul/gisknife) 已公开。提交 `a44629a` 的 [GitHub Actions](https://github.com/reed-soul/gisknife/actions/runs/44891200576) 在 Ubuntu 和 macOS 上均通过，两个平台的候选包均按各自清单核对了 SHA-256。正式发包使用待发布提交重新验收的产物。
3. **发布账号与首次发包。** 确认账号有权向 npm `@gisknife` 发布，并检查 `gisknife` 包名。为 PyPI `gisknife-engine` 配置 [Trusted Publisher](https://docs.pypi.org/trusted-publishers/creating-a-project-through-oidc/)：所有者 `reed-soul`、仓库 `gisknife`、工作流 `publish-python.yml`、环境 `pypi`。将该 GitHub 环境限制到 `master`。从 `master` 手动运行发布工作流；默认只验收，明确授权后启用 `publish`，两平台通过才上传 Python 包。确认公共 PyPI 可安装后再按依赖顺序发 npm：core、picker、mcp-apps、webmcp-bridge、a2ui-catalog → mcp → gisknife。npm 候选标签也是公开的；验证后再设默认标签。
4. **从公网重新安装。** 在没有 checkout、`UV_FIND_LINKS` 或工作区链接的环境，从公共源安装指定版本并跑 `doctor`、轻/重转换与 stdio。GitHub 安装链接须在临时 HOME 再走一次。以上未通过，不宣布正式上线。
5. **网站单独上线。** 另行确认后，从干净工作区发布到该项目的 Cloudflare Worker；先记录可回滚版本，再测真实域名的原转换下载、导航和新交接。若失败，恢复已记录的 Worker 版本，或用 `VITE_GISKNIFE_HANDOFF=off` 重新部署并复测旧路线。

**发包回滚：** npm 移走有问题的默认标签并标记坏版本弃用；PyPI yank 有问题的版本；GitHub 标记候选撤回。首发无上一版，不假设存在可切回的版本。不要覆盖已发布的同号包，修复使用新版本。仅回滚代码不能撤回用户已下载的数据。
